# Path To 1.0

Status: `Direction`

## Product Definition

GeoTurf `1.0` should be a stable WGS84 library for measurements, spatial
predicates, route analysis, and focused geometry transformations. It does not
require full TurfJS parity before `1.0`.

Polygon set operations, buffering, feature-property preservation, spatial
indexes, grids, and statistical analysis remain valuable, but are not `1.0`
requirements unless a real caller makes them necessary.

## Version Path

| Version | Intent | Compatibility posture |
| --- | --- | --- |
| `0.5` | Quality Foundations | Deliberate breaking-change window for existing contracts. |
| `0.6` | Line Analysis Foundations | New stable route-analysis interfaces. |
| `0.7` | Boolean relationships and geometry hygiene | New stable predicate and normalization interfaces. |
| `0.8` | Advanced geodesics | Add rhumb and route-shape tools with documented accuracy. |
| `0.9` | Release candidate | Freeze public interfaces; only correctness, documentation, and compatibility work. |
| `1.0` | Stable release | Publish the compatibility promise after all gates pass. |

Version numbers are planning milestones, not release authorization. A release
still requires explicit instruction and the normal changelog/version/tag work.

## `0.5` Contract Reset

Do these changes before line and boolean work depends on today’s accidental
behavior:

- Return raw geodesic values from `distance/3`, keeping display rounding an
  explicit caller decision.
- Define `close_to/4` threshold inclusivity.
- Preserve independent coordinate paths for all measurements.
- Define empty, degenerate, unsupported-unit, and invalid-SRID behavior.
- Normalize public option names and types, especially `:units`.
- Choose one output SRID convention for derived geometry.
- Decide the canonical `length` interface and any compatibility path from
  `length_of/2`.

Each decision must be tested, documented, and recorded in the Quality
Foundations plan. Create an ADR only if a decision is hard to reverse,
non-obvious, and selected after a real trade-off.

## `1.0` Gates

Do not release `1.0` until all of these are true:

- [ ] Every public function documents accepted geometry, units, SRID behavior,
  precision, errors, and output shape.
- [ ] The supported geometry types and collection semantics are complete and
  covered by tests.
- [ ] TurfJS-parity functions have focused conformance fixtures or documented
  intentional deviations.
- [ ] Public interfaces have been stable through at least the `0.9` cycle;
  remaining deprecations are resolved.
- [ ] CI verifies the documented Elixir and OTP support range, formatting,
  tests, Dialyzer, Credo, and documentation generation.
- [ ] The package release process has been exercised successfully from the
  documented `Unreleased` changelog state.

## Decision Points

Before `0.8`, decide whether GeoTurf will own a projection adapter and which
accuracy/dependency strategy it will use for buffers and polygon clipping.
Do not add either feature on an implicit or undocumented projection model.
